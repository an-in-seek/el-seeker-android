# PRD: ElSeeker 운영 지원 후원 안내 기능

## 0. 문서 상태 및 정책 게이트

상태: **구현 전 보완 완료, 단 앱스토어 정책 게이트 통과 전 배포 금지**

본 문서는 앱 내 결제 기능이 아니라 외부 후원 안내 기능을 정의한다. 다만 Google Play, App Store 심사에서 후원/기부/외부 결제 링크는 정책 해석 리스크가 있으므로, 구현 완료와 별개로 아래 게이트를 통과해야 앱 배포 대상에 포함할 수 있다.

정책 확인 기준일: **2026-06-30**

공식 정책 참조:

* Google Play: `https://support.google.com/googleplay/android-developer/answer/10281818`
* Apple App Review Guidelines: `https://developer.apple.com/app-store/review/guidelines/`

### 0.1 배포 전 필수 확인

* 후원 수령 주체를 확정한다.
  * 개인 개발자/운영자에 대한 선택적 운영 지원인지
  * 승인된 비영리 단체 모금인지
  * 법인/단체의 서비스 운영비 후원인지
* 후원금은 앱 내 디지털 콘텐츠, 기능, 권한, 광고 제거, 뱃지, 랭킹, 노출, 고객지원 우선권과 연결하지 않는다.
* 후원금이 대가성 결제가 아니며, 후원 여부에 따라 앱 경험이 달라지지 않는다는 문구를 앱 내부와 외부 페이지에 모두 노출한다.
* 공식 정책상 "전액 수령자 전달" 조건이 적용되는 후원 모델인지 확인하고, 외부 송금/결제 수단의 수수료와 실수령 범위를 외부 페이지에 고지한다.
* Android/iOS 네이티브 앱 심사 제출 전 App Review/Play Console 검토 노트에 후원 기능의 성격과 외부 열기 방식을 명시한다.
* 정책 해석이 불명확하거나 심사 리스크가 높다고 판단되면 네이티브 앱 WebView에서는 후원 메뉴를 비활성화하고 일반 웹 브라우저에서만 노출한다.

### 0.2 정책상 금지되는 구현

* 앱 내부에서 후원 금액, 결제 수단, 계좌번호, 송금 링크, QR 코드를 직접 노출
* 앱 내부에서 토스/카카오페이/은행 앱 딥링크를 직접 호출
* 후원 완료 여부 확인, 후원자 식별, 후원 내역 조회
* 후원자를 위한 디지털 보상, 프리미엄 기능, 광고 제거, 뱃지, 칭호, 랭킹 가산점
* 후원을 유도하기 위해 앱 기능을 제한하거나 반복 모달을 노출

### 0.3 플랫폼별 배포 결정 규칙

앱 배포 전 다음 노출 상태를 릴리스 체크리스트에 각각 기록한다.

* `ANDROID_WEBVIEW_ENABLED` 또는 `ANDROID_WEBVIEW_DISABLED`
* `IOS_WEBVIEW_ENABLED` 또는 `IOS_WEBVIEW_DISABLED`
* `WEB_BROWSER_ENABLED` 또는 `WEB_BROWSER_DISABLED`

Android WebView 후원 진입점은 다음 조건을 모두 만족할 때만 활성화한다.

* 후원금의 100%가 명시된 수령자에게 전달된다.
* 후원이 앱 내 디지털 콘텐츠, 서비스, 기능, 뱃지, 이모지, 광고 제거, 우선 지원, 랭킹 등과 연결되지 않는다.
* 수령 주체가 Google Play 정책상 user-to-creator 또는 peer-to-peer contribution으로 해석 가능한지 확인했다.
* 위 조건 중 하나라도 충족하지 못하거나, 운영비 후원이 Google Play Billing 대상인지 불명확하면 Android WebView에서는 후원 메뉴를 비활성화한다.

본 PRD는 Google Play Billing 연동을 제외하므로, Android에서 Play Billing이 필요하다고 판단되면 이 기능은 Android 앱 MVP 범위에서 제외한다.

iOS WebView 후원 진입점은 다음 조건을 모두 만족할 때만 활성화한다.

* 앱 내부 수금이 아니라 Safari 등 앱 외부 브라우저에서만 수금된다.
* 개인 간 금전 선물 또는 앱 밖 자율 후원 안내로 볼 수 있고, 완전 선택 사항이며, 100%가 수령자에게 전달되고, 디지털 콘텐츠/서비스와 연결되지 않는다.
* App Review 리스크 검토를 통과했다.

승인된 비영리 단체의 Apple Pay direct fundraising은 본 MVP 범위가 아니다. 해당 경로가 필요하면 Apple Pay, 세금 영수증, 사용처 공개, 관련 법 준수, 심사 메타데이터를 포함하는 별도 PRD로 분리한다.

위 조건을 충족하지 못하거나 수령 주체가 불명확하면 iOS WebView에서는 후원 메뉴를 비활성화한다.

## 1. 목적

ElSeeker 서비스의 서버, 도메인, 유지보수 비용을 사용자가 자율적으로 지원할 수 있도록 후원 안내 진입점을 제공한다.

본 기능은 **앱 내 결제 기능이 아니며**, 후원 완료 처리도 하지 않는다. 앱 내부는 외부 후원 안내 페이지로 이동하기 전의 설명, 고지, 외부 열기 동작만 책임진다.

### 대상 플랫폼

본 기능은 **하이브리드 앱**(WebView 안에서 동작하는 Thymeleaf 웹 콘텐츠 + Android/iOS 네이티브 래퍼)을 전제로 한다.

동일한 웹 페이지가 일반 PC/모바일 브라우저에서도 서빙될 수 있으므로, 모든 동작은 다음 두 환경을 모두 고려한다.

* WebView 내부(네이티브 브릿지 사용 가능)
* 일반 웹 브라우저(브릿지 없음, 폴백 동작)

## 2. 핵심 원칙

후원 여부와 관계없이 모든 사용자는 앱의 모든 기능과 콘텐츠를 동일하게 이용할 수 있어야 한다.

후원은 앱 내 기능, 콘텐츠, 권한, 광고 제거, 프리미엄 혜택과 연결하지 않는다.

후원 흐름은 회원 계정과 연결하지 않는다. 로그인 사용자가 후원 안내 메뉴를 눌러도 후원 관심, 후원 여부, 후원 금액을 회원 식별자와 결합하지 않는다.

## 3. 제공 범위

앱 내부에는 다음 기능만 제공한다.

* 마이페이지에 "운영 지원하기" 메뉴 추가
* 운영 지원 안내 화면 제공
* 외부 후원 안내 페이지로 이동한다는 사전 고지 노출
* "후원 안내 페이지 열기" 버튼 제공
* 버튼 클릭 시 외부 브라우저로 후원 안내 페이지 이동
* 외부 열기 실패 시 안내 메시지와 URL 복사 대체 수단 제공
* 익명 클릭 이벤트 로깅

진입점 정책:

* 앱 내부 진입점은 마이페이지에 둔다.
* 후원 안내 자체는 회원 전용 기능이 아니다.
* 외부 URL 직접 접근은 인증과 무관하게 가능해야 한다.
* 후원 화면이나 외부 페이지에서 로그인 유도, 회원 정보 입력, 후원자 확인을 요구하지 않는다.
* 후원 메뉴와 CTA는 기본 hidden 상태로 렌더링한다.
* JS는 서버가 내려준 플랫폼 노출 플래그와 WebView marker를 모두 확인한 뒤에만 메뉴/CTA를 노출한다.
* 일반 브라우저는 `WEB_BROWSER_ENABLED`일 때만 노출한다.
* Android/iOS WebView는 각 플랫폼 gate가 `*_WEBVIEW_ENABLED`이고 `window.ElSeekerWebView` marker가 정상 주입된 경우에만 노출한다.
* iOS WebView marker 주입 실패는 웹에서 안정적으로 판별할 수 없으므로, 네이티브 앱에서는 서버/앱 설정으로 메뉴를 기본 미노출 처리한다.

라우트 정책:

* 앱 내부 안내 화면: `/web/support/donation`
* 앱 내부 안내 템플릿: `support/donation.html`
* 앱 내부 안내 리소스: `css/support/donation.css`, `js/support/donation.js`
* 외부 후원 페이지: `https://elseeker.com/support`
* 같은 Spring 서비스에서 외부 페이지를 제공하는 경우 `/support` 또는 `/web/support/donation` 중 하나로 통일하지 않는다. 앱 내부 안내와 외부 후원 페이지는 목적이 다르므로 라우트를 분리한다.

## 5. 사용자 흐름

1. 사용자가 앱에서 마이페이지로 이동한다.
2. "운영 지원하기" 메뉴를 선택한다.
3. 앱은 운영 지원 안내 문구와 "외부 페이지로 이동합니다" 고지를 보여준다.
4. 사용자가 "후원 안내 페이지 열기" 버튼을 누른다.
5. 앱은 외부 브라우저로 후원 안내 페이지를 연다.
   * WebView 환경: 네이티브 브릿지를 통해 외부 브라우저로 연다.
   * 일반 브라우저 환경: 새 탭 또는 현재 탭으로 연다.
6. 외부 열기에 실패하거나 안전한 외부 열기 여부를 판단할 수 없으면 사용자에게 안내 후 URL 복사 버튼을 제공한다.
7. 사용자는 외부 페이지에서 후원 방법을 확인한다.
8. 사용자는 선택적으로 정책 게이트를 통과한 외부 수단을 통해 후원한다.

## 6. 화면 문구

### 앱 내부 문구

ElSeeker는 무료로 제공되는 성경 학습 서비스입니다.

서비스 운영에는 서버, 도메인, 유지보수 비용이 발생합니다. 서비스가 유익하셨다면 자율적으로 운영을 지원하실 수 있습니다.

후원은 선택 사항이며, 후원 여부와 관계없이 앱의 모든 기능은 동일하게 제공됩니다.

후원은 앱 내 콘텐츠, 기능, 권한, 광고 제거, 뱃지, 칭호와 연결되지 않습니다.

### 외부 이동 고지 문구

후원 안내 페이지는 앱 외부의 별도 브라우저에서 열립니다.

앱 안에서는 결제나 송금을 처리하지 않습니다.

### 실패 안내 문구

외부 브라우저를 열 수 없습니다. 아래 URL을 복사해 브라우저에서 직접 열어 주세요.

### 버튼 문구

후원 안내 페이지 열기

### 대체 버튼 문구

URL 복사

## 7. 외부 후원 페이지

URL: `https://elseeker.com/support` (확정)

외부 후원 페이지는 본 기능의 필수 의존성이다. 앱 내부 구현은 외부 페이지를 직접 만들지 않더라도, 배포 전 다음 조건을 충족해야 한다.

* `https://elseeker.com/support`가 실제로 접근 가능해야 한다.
* HTTP는 HTTPS로 리다이렉트되어야 한다.
* 단축 URL을 사용하지 않는다.
* 외부 페이지가 다른 결제/송금 페이지로 이동시키는 경우에도 HTTPS만 허용한다.
* 외부 페이지는 앱 WebView가 아니라 일반 브라우저에서 열려야 한다.
* 같은 Spring 서비스에서 제공한다면 `/support` 라우트를 명시적으로 추가하거나, 프록시/정적 호스팅에서 해당 경로를 제공해야 한다.
* 외부 페이지가 아직 준비되지 않았거나 임시/placeholder 상태이면 앱 내부 후원 메뉴를 노출하지 않는다.

외부 후원 페이지에는 다음 내용을 제공한다.

* ElSeeker 서비스 소개
* 후원 목적 안내
* 후원금 사용처 안내
* 후원 수령 주체
* 외부 송금/결제 수단의 수수료 및 실수령 범위
* 후원은 자율이라는 고지
* 후원 여부와 앱 내 기능 제공이 무관하다는 고지
* 후원으로 제공되는 디지털 보상이 없다는 고지
* 개인정보 수집 여부 및 문의처
* 환불/정정 문의 방법
* 정책 게이트를 통과한 외부 후원 수단

외부 후원 페이지에는 앱 심사 정책을 위반할 수 있는 문구를 넣지 않는다.

금지 문구 예:

* 후원하면 더 많은 기능을 제공한다.
* 후원자에게 특별 콘텐츠를 제공한다.
* 후원자에게 광고 제거 혜택을 제공한다.
* 후원자를 앱 안에서 표시한다.
* 후원하면 빠른 답변을 받을 수 있다.

## 8. 기술 요구사항

### 8.1 외부 브라우저 열기

후원 안내 페이지와 송금 링크는 WebView 내부에서 열지 않고 외부 브라우저로 연다.

앱 내부(WebView 화면)에는 계좌번호, 송금 링크, QR 코드를 직접 노출하지 않는다.

WebView 여부를 안전하게 판단할 수 없으면 외부 링크를 자동으로 열지 않는다. 대신 사용자가 URL을 복사할 수 있도록 한다.

### 8.2 WebView 네이티브 브릿지

웹 버튼 클릭이 네이티브 외부 열기를 호출하는 규약을 다음과 같이 정의한다.

* 인터페이스: `window.AppBridge.openExternal(request)`
* 요청 객체:
  * `requestId`: 웹에서 생성한 일회성 문자열
  * `url`: 고정 URL `https://elseeker.com/support`
  * `source`: 고정값 `support`
* 네이티브 동작:
  * Android: 검증된 URL만 `Intent.ACTION_VIEW`로 외부 브라우저 실행
  * iOS: 검증된 URL만 `UIApplication.open(_:)`으로 외부 브라우저 실행
* 결과 콜백:
  * `window.onExternalOpenResult({ requestId, success, reason })`
  * `requestId`가 일치하지 않는 콜백은 무시한다.

브릿지 보안 규칙:

* 허용 URL은 `https://elseeker.com/support` 정확 매칭을 기본값으로 한다.
* `http:`, `javascript:`, `intent:`, 커스텀 스킴, 사용자 입력으로 만든 URL은 거부한다.
* 네이티브 레이어에서도 allowlist를 검증한다. 웹 검증만 신뢰하지 않는다.
* 브릿지를 사용할 수 없거나 예외가 발생하면 fail-closed 처리한다.
* 같은 요청의 중복 클릭은 1회만 처리한다.
* 콜백이 일정 시간 내 오지 않으면 실패 안내와 URL 복사 버튼을 노출한다.

### 8.3 환경 감지 및 폴백

웹 페이지는 WebView 내부인지 일반 브라우저인지 감지하여 분기한다.

네이티브 래퍼는 WebView 생성 직후 페이지 스크립트 실행 전에 다음 marker를 주입해야 한다.

* `window.ElSeekerWebView = { platform: "android" | "ios", version: string, supportsOpenExternal: boolean }`

WebView marker 정책:

* Android/iOS 앱 WebView는 `window.ElSeekerWebView` 주입이 필수다.
* marker가 있고 `supportsOpenExternal=true`이며 `window.AppBridge.openExternal`이 존재할 때만 브릿지를 통해 외부 브라우저를 연다.
* marker가 있지만 브릿지나 `supportsOpenExternal`이 없으면 자동 열기 금지 및 URL 복사 안내를 제공한다.
* marker가 없지만 Android WebView UA 토큰(`; wv)`) 등으로 WebView가 의심되면 자동 열기 금지 및 URL 복사 안내를 제공한다.
* iOS는 UA만으로 WKWebView를 안정적으로 판별하지 않는다. iOS 네이티브 앱에서는 marker 주입 실패 시 후원 메뉴를 미노출하는 것을 기본값으로 한다.

분기 규칙:

* `window.ElSeekerWebView.supportsOpenExternal=true`이고 `window.AppBridge.openExternal`이 존재하면 브릿지를 통해 외부 열기
* 일반 웹 브라우저로 판단되면 `<a target="_blank" rel="noopener noreferrer">` 방식으로 새 탭 열기
* 팝업 차단 또는 새 탭 열기 실패 시 현재 탭 이동 또는 URL 복사 안내 제공
* 외부 열기 실패 시 안내 메시지 노출 및 URL 복사 대체 수단 제공

일반 브라우저에서 새 탭 열기 성공은 외부 페이지의 실제 로드 성공을 의미하지 않는다. 로깅은 "외부 브라우저 열기 시도 결과" 수준으로만 해석한다.

## 9. 이벤트 로깅

### 9.1 수집 이벤트 및 수집 주체

| 이벤트명 | 발생 시점 | 수집 주체 |
| --- | --- | --- |
| `support_menu_click` | "운영 지원하기" 메뉴 선택 | 웹 |
| `support_page_open_click` | "후원 안내 페이지 열기" 버튼 클릭 | 웹 |
| `support_external_open_dispatched` | 외부 브라우저 열기 요청을 브릿지/브라우저에 전달 | 웹 |
| `support_external_open_dispatch_fail` | 브릿지 호출, 팝업, URL 검증, 환경 판별 실패 | 웹 또는 네이티브 콜백 |
| `support_url_copy_click` | URL 복사 버튼 클릭 | 웹 |

성공/실패 이벤트는 외부 페이지 로드나 후원 완료를 의미하지 않는다. 네이티브 콜백은 "외부 열기 요청 전달 성공/실패"만 기록한다.

### 9.2 저장소 정책

후원 이벤트는 기존 방문 로그 테이블 `site_visit_event`에 직접 적재하지 않는다.

이유:

* `site_visit_event`는 로그인 사용자에 대해 `member_uid`를 저장한다.
* 후원 메뉴는 마이페이지에서 노출되므로 인증 사용자와 결합될 가능성이 높다.
* 후원 관심 클릭을 회원 식별자와 결합하면 "후원자 식별 없음" 원칙이 약해진다.

권장 구현:

* 별도 테이블: `support_event`
* 별도 API: `POST /api/v1/analytics/support/events`
* 인증 불필요: `permitAll`
* 저장 컬럼:
  * `id`
  * `visitor_id`: `es_visitor_id`를 pepper 포함 SHA-256으로 해시한 값
  * `event_type`
  * `is_bot`
  * `occurred_at` (UTC)
  * `occurred_date` (Asia/Seoul)
  * `created_at`
  * `updated_at`
* 저장 금지 컬럼:
  * `member_uid`
  * `member_id`
  * 이메일
  * 닉네임
  * 원본 IP
  * 전체 User-Agent
  * 전체 Referer URL
  * 후원 금액
  * 송금자명

`app_install_banner_event`의 익명 이벤트 저장 방식(회원 식별자 미저장, visitor 해시)을 우선 참고한다.

### 9.3 식별자 정책

클릭 이벤트는 **익명 집계**를 원칙으로 한다.

후원 여부 추론이나 후원자 식별 목적의 회원 식별자 결합은 하지 않는다. 관리자 화면에서도 visitor 단위 원시 로그를 회원 데이터와 조인할 수 없도록 설계한다.

### 9.4 미수집 정보

다음 정보는 수집하지 않는다.

* 후원 여부
* 후원 금액
* 송금자명
* 계좌 정보
* 결제 수단 정보
* 후원 내역
* 외부 결제/송금 페이지 행동

### 9.5 보관 기간 및 개인정보처리방침

`support_event`는 익명 이벤트라도 후원 관심 행동 로그이므로 최소 보관 원칙을 적용한다.

* 원시 이벤트 보관 기간: 최대 90일
* 집계 테이블: `support_event_daily_stat`
* 집계 단위: `occurred_date`, `event_type`, `count`
* 집계/정리 배치: 일 1회 실행
* 배치 처리 순서: 전날까지의 원시 이벤트를 `support_event_daily_stat`에 upsert한 뒤, 90일 초과 `support_event` row를 삭제한다.
* 배치 실패 시 다음 실행에서 같은 기간을 재처리할 수 있도록 idempotent upsert를 사용한다.
* 90일 이후: 일자/이벤트 타입 단위 집계값만 남기고 원시 이벤트 삭제
* 관리자 조회: 일자별 집계와 이벤트 타입별 집계만 제공한다.
* 관리자 API: `GET /api/v1/admin/analytics/support/events/daily`
* 관리자 API는 `support_event_daily_stat`만 조회하고 `support_event` 원시 로그를 직접 반환하지 않는다.
* 관리자 화면에서 단일 visitor의 이벤트 타임라인을 조회하지 않는다.
* 개인정보처리방침에는 "운영 지원 안내 클릭 등 익명 이용 통계" 수집 목적, 보관 기간, 미수집 항목을 반영한다.
* 보관 기간 변경 시 개인정보처리방침과 본 PRD를 함께 갱신한다.

## 10. 보안 요구사항

* 후원 URL은 서버 또는 JS 상수의 고정값으로 관리한다.
* 사용자 입력값으로 redirect URL을 전달받지 않는다.
* 단축 URL을 사용하지 않는다.
* 외부 URL allowlist를 웹과 네이티브 양쪽에서 검증한다.
* CSP, XSS 방어, `rel="noopener noreferrer"`를 적용한다.
* 브릿지 호출은 `source=support`와 고정 URL만 허용한다.
* 클릭 로깅 API는 rate limit을 둔다.
* 로깅 실패는 사용자 흐름을 막지 않는다.

## 12. 최종 결론

ElSeeker 후원 기능은 다음 구조로 구현한다.

순수 자율 후원 안내:

* 앱 내 혜택 없음
* 후원자 식별 없음
* 앱 내부 결제 없음
* 앱 내부 송금 정보 노출 없음
* 외부 후원 안내 페이지 연결
* 후원 여부와 기능 제공 무관 고지

하이브리드 구조에서는 **웹 안내 화면 + 네이티브 브릿지 외부 열기 + 일반 브라우저 폴백 + WebView fail-closed**를 모두 보장한다.

초기 MVP는 "운영 지원하기 메뉴 + 안내 문구 + 외부 이동 고지 + 외부 후원 페이지 연결 + 익명 이벤트 로깅 + URL 복사 대체 수단" 범위로 진행한다.

단, Android/iOS 앱 배포에는 0장의 정책 게이트 통과가 선행되어야 한다.
